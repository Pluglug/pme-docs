Modal Operator Editor¶

Modal Operator は、hotkey を押してから確定 / 取消するまで Blender を一時的に専用モードに固定する対話ツールを作成するエディターです。マウス移動・マウスホイール・サブホットキーを入力として、連続的にプロパティを変更したり処理を呼び出したりします。

名前付きオペレーター

モーダルオペレーターのしくみ¶

Modal Operator は、起動 hotkey から確定 / 取消までの間、次の順序で動作します。

[起動 hotkey]
   ↓
On Invoke          ← モーダル開始時に 1 回だけ走る
   ↓
[サブホットキー押下 / マウス操作のたびに繰り返し]
   On Update       ← 何か操作されるたびに走る
   Command/Property ← 対応するサブホットキー / マウス操作が来たときに走る
   ↓
[ユーザーが確定 or 取消]
   ↓
On Confirm  または  On Cancel
   ↓
[モーダル終了]

エディター画面¶

トップバー¶

エディター画面の最上段、メニュー名の左右に並ぶ操作です。画面の見た目はエディターによって少し違いますが、項目の意味は共通です。

有効/無効:

メニュー全体を有効化/無効化します。無効化すると hotkey だけでなく、open_menu() / pme.invoke_pm() などのスクリプト経路、登録済みメニューやパネル経路（Extend Panel / Side Panel / Hidden Panel Group）からも実行されなくなります。
hotkey だけを外したい場合は、メニューを無効化するのではなく Hotkey 設定 を編集してください。

プレビュー:

メニューをその場で表示して、レイアウトや並びを確認します。プレビュー中は実際の context でコマンドは実行されません。プレビューが用意されているエディター（Pie Menu / Pop-up Dialog / Regular Menu）でのみ表示されます。

メニュー選択:

編集対象のメニューを切り替えます。アイコンは現在のメニュー種別（Pie / Popup / Regular / Modal …）を示します。検索や種別フィルターで絞り込んだ一覧が出ます。

メニュー名:

メニューの名前です。表示用ラベルであると同時に、他のメニューや Python コードからこのメニューを呼び出すときの識別子になります。open_menu("名前") で呼び出す場合も、ここで設定した名前を使います。
PME2 では MENU スロット経由のメニュー間参照に uid を持たせるようになり、MENU スロットや Pop-up Dialog / Floating Panel の Dialog リンクは名前を変えても壊れません。一方で、COMMAND / CUSTOM タブ内で open_menu("名前") / draw_menu("名前") のように名前文字列で呼び出している箇所は、現状まだ名前ベースです。この経路の uid 化は開発中で、いまは PME 側で参照を追跡できないので、メニュー名を変更したらこれらのコードも合わせて直してください。

被参照ボタン:

このメニューを参照している別のメニューがある場合に表示されます。クリックすると参照元の一覧が出て、そこからジャンプできます。Macro から別の Stack Key を呼んでいる、Regular Menu のスロットから Pop-up Dialog を呼んでいる、といった依存関係を追うときに使います。

Tag:

メニューの分類・検索用ラベルです。クリックするとタグ編集ポップアップが開き、複数のタグを付けられます。
Tag を付けておくと、Pie Menu Editor の一覧画面で 絞り込み・グループ表示ができ、pm_enable_by_tag("名前", True) でセット単位での有効化にも使えます。Settings > General > Auto-Tag New Menus を有効にすると、現在のタグフィルタで新規メニューに自動でタグが付きます。

ドキュメント:

PME のオンラインドキュメント（このサイト）の該当ページを開きます。

詳細設定トグル:

Description（説明文）・Poll（実行可否）・そしてエディターごとの追加オプションのパネルを開閉します。詳細設定を持たないエディター（Hidden Panel Group）もあります。

Hotkey 設定（モーダルの起動キー）¶

キーマップ

Blenderのキーマップは階層構造です。PMEのホットキーもその中で解決されるため、どのKeymapに置くかで挙動が変わります。既存のホットキーのKeymapやアクションを調べるには、エディタの+ボタンを使用してください。

  • 参考: BlenderのKeymapとPME

ホットキーモード

  • Press: キーを押す

  • Hold: キーを押し続ける

  • Tweak: キーを押しながらマウスを動かす

  • Double Click: キーをダブルクリックする

モディファイア

Any modifier は Ctrl / Shift / Alt / OSKey の任意の組み合わせです。コンテキスト感応ツールの作成に使えます。

このアドオンではマウスボタンをモディファイアとして使えます（例: LMB+Tab / RMB+Tab / MMB+Tab）。

print("Ctrl is pressed" if E.ctrl else "Ctrl isn't pressed")

ここで設定するのはモーダル全体を起動する hotkey です。サブホットキーは各スロット側で個別に設定します。

メニュースロット¶

スロットは「実行ルール」として上から順に並びます。各スロットは次の情報を持ちます。

  • タイプ（Command / Property / On Invoke / On Confirm / On Cancel / On Update）

  • トリガー（サブホットキー / マウス移動 / マウスホイール / lifecycle イベント）

  • 実行内容（Python コードまたはプロパティパス）

スロットの追加・削除・並び替え・無効化はすべて可能です。

On Update の配置位置による対象¶

On Update は配置位置によって対象が変わります。

  • すべてのサブホットキーの前に置いた場合 — どのサブホットキーが押されてもその On Update が走ります。

  • 特定のサブホットキー（Command / Property）の直後に置いた場合 — そのサブホットキーが押されたときだけ On Update が走ります。

詳細設定¶

Description:

自作のマクロや複雑なコマンドを後で見返したとき、何のために作ったか分からなくなる。PME ではメニューにもスロットにも説明文を残せます。
右のスクリプトトグル を ON にすると、Description は Python 式として扱われ、毎回評価された戻り値が表示されます。現在のモードや選択数を反映した動的な説明文にできます。

return f"Active: {C.active_object.name if C.active_object else '(none)'}"

説明文を書いていないメニューでも、tooltip は参照先のメニュー名を自動で表示します。書いておくと、その内容で上書きされます。共有時に意図が伝わる、後から見返したときに迷子にならない、というのが Description の目的です。

Poll:

「今の Blender の状態で、このメニューを実行してよいか」を Python の式で判定する仕組みです。式の戻り値が True ならメニューが実行され、False なら hotkey や UI から呼ばれてもスキップされます。

ao = C.active_object; return ao and ao.type == 'MESH'

Poll は hotkey 経由の呼び出しだけでなく、HOLD / TWEAK / CHORD、open_menu() / pme.invoke_pm() などのスクリプト経路、editor preview、Popup Dialog や通常メニューの描画、Macro / Modal / Sticky / Floating Panel からの呼び出しでも確認されます。設定しておけば、現在の context では使えないメニューが別経路から実行されてしまうケースを防げます。

右の から、よく使う条件をその場で追加できる Poll 補助メニューが開きます（モード判定・空 Poll の挿入・Cut / Copy / Paste など）。条件の書き方の入口は Poll Method の基礎 にまとめてあります。

Confirm on Release:

起動 hotkey を離した瞬間に On Confirm を実行してモーダルを終了します。

Block UI:

モーダル中、画面の他の UI（ボタン、メニューなど）への操作をブロックします。

Lock:

モーダルが起動した area / region に処理を固定します。マウスが別の area に乗っても、モーダルは元の area の context で動き続けます。

Added in version 2.0.4: Lock 有効時のマウス移動でプロパティを編集している間、カーソルが起動元エリア内へ戻りやすくなりました。

スロットタイプ（Modal 固有）¶

Command¶

サブホットキーが押されたときに実行する Python コードを書きます。スロットエディタ内でこのスロット用のサブホットキーを 1 つ割り当てます。

bpy.ops.transform.resize('INVOKE_DEFAULT')

C.scene.tool_settings.use_proportional_edit = not C.scene.tool_settings.use_proportional_edit

Property¶

プロパティへのパスを指定し、どの入力で変えるかを選びます。Property タブの中で入力モードを 3 つから選択します。

入力モード

挙動

Hotkey

サブホットキーを押している間、マウス移動で値が変わります。

Mouse Move

サブホットキーは使わず、マウス移動だけで値が変わります。他のサブホットキーを塞ぐため、Confirm on Release と組み合わせて確定経路を確保します。

Mouse Wheel

マウスホイールの上下で値を増減します。列挙型 / 離散値向きです。

On Invoke¶

モーダルが起動した瞬間に 1 回だけ実行する Python コードを書きます。初期値の保存、オーバーレイ描画の開始、起動時 context の記録などに使います。

pme.start_size = paint_settings().brush.size

On Confirm¶

ユーザーが確定したとき（Enter キー / Confirm on Release / confirm() 関数）に実行する Python コードを書きます。

On Cancel¶

ユーザーが取消したとき（Escape キー / 右クリック / cancel() 関数）に実行する Python コードを書きます。

On Update¶

モーダル中に何かが起きるたびに走る Python コードを書きます。配置位置による対象の違いは「メニュースロット」節を参照してください。

Python から確定・取消する¶

Command スロットや On Update の中から、Modal を Python で終了させる関数が使えます。

confirm()

Modal Operator を確定して終了します。On Confirm が走ります。

戻り値:

True

cancel()

Modal Operator を取消して終了します。On Cancel が走ります。

戻り値:

True

if condition_met:
    confirm()

if invalid_input:
    cancel()

応用的な使い方¶

マウス移動でブラシサイズを連続調整¶

Property スロットでブラシサイズをバインドし、入力モードを Mouse Move、起動キー設定で Confirm on Release を有効にすると、押している間マウス移動で値が変わり、離すと確定する操作になります。

軸ごとのサブホットキーで対象を切り替える¶

複数の Property スロットを並べ、それぞれに別のサブホットキー（X / Y / Z など）を割り当てます。モーダル中にどのキーを押すかで調整対象が切り替わります。

マウスホイールで列挙プロパティを巡回¶

Property スロットで列挙型プロパティ（C.space_data.shading.type など）を指定し、入力モードを Mouse Wheel にします。ホイールを回すと値が次々と切り替わります。

Macro の途中で対話的な調整を入れる¶

Macro Operator の Menu スロットに Modal Operator を指定すると、Macro の途中でユーザー入力を待つ調整ステップを挟めます。確定するまで次のスロットには進みません。

On Invoke / On Cancel で「キャンセルしたら元に戻す」¶

On Invoke で現在値を pme 名前空間に保存し、On Cancel でその値に戻すパターンです。

pme.start_size = paint_settings().brush.size

paint_settings().brush.size = pme.start_size

release_confirm を渡す Blender ネイティブ Modal の呼び出し¶

Blender の Transform 系のように、ネイティブ側にも release_confirm がある operator は、Command スロットから直接呼び出して PME 側の確定挙動と揃えられます。

bpy.ops.transform.resize('INVOKE_DEFAULT', release_confirm=True)

Blender の Modal Map との違い

Modal Operator Editor は、Blender 内部の modal keymap（Transform や Knife ツール内のキー割り当て表）を直接編集する機能ではありません。PME が用意する Modal 風ミニツールを構築する仕組みです。
