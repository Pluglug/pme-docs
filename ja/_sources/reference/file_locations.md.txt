(user_resources)=

# 保存先とフォルダ構成

PME は、登録した **リソースフォルダー**からスクリプトとカスタムアイコンを読み込みます。
各フォルダーを名前とパスで管理し、メニューバックアップとログの保存先は別に設定します。

:::{versionchanged} 2.2.0
名前付きの複数リソースフォルダーと 実行中の Blender の実行ファイル（Windows では `blender.exe`） があるフォルダーを基準とする相対パスに対応し、全登録先のスクリプト・アイコンを利用できるようになりました。
設定を起動設定ファイルへ移し、Quick Locations を各登録先に対応させ、Examples はパッケージを直接参照する形に変更しました。
:::

## リソースフォルダーの構成

**PME が参照するサブフォルダー名は固定です。** 各リソースフォルダーを、次の構成で扱います。

```text
Pie Menu Editor/                # 登録するフォルダー。名前と場所は変更可能
├── scripts/
│   ├── autorun/
│   ├── register/
│   └── unregister/
├── icons/                     # アイコン用フォルダーとして登録（下記）
└── exports/
```

| 配置場所 | 用途 |
|----------|------|
| `scripts/` | ユーザースクリプト。下位フォルダーに整理できます。 |
| `scripts/autorun/` | PME の起動・有効化時に自動実行するスクリプト。 |
| `scripts/register/` | `autorun/` の後に実行する初期化用スクリプト。 |
| `scripts/unregister/` | PME の無効化時に実行する後始末用スクリプト。 |
| `icons/` | カスタムアイコン。{guilabel}`Custom Icon Directories` に登録したときに使います。 |
| `exports/` | メニューを Import・Export するときの Quick Locations の移動先。 |

使わないサブフォルダーはなくても登録できます。行末メニューの {guilabel}`Create Subfolders` は、
既存のリソースフォルダーに不足する `scripts/`・`exports/` を作成します。

**カスタムアイコンは {guilabel}`Custom Icon Directories` に別に登録します。** 登録したアイコン用フォルダーの直下にある `.png` を使うため、
PNG を並べたフォルダーをそのまま追加できます。
リソースフォルダーを **+** で追加したとき、その中に `icons/` があれば {guilabel}`Custom Icon Directories` にも追加します。
アイコン用フォルダーは後からリソースフォルダーを変更しても追従しません。0件にもでき、その場合は同梱アイコンだけを使います。
`autorun/`・`register/`・`unregister/` は自動実行が必要なときに作成してください。
登録や閲覧だけでサブフォルダーを作成したり、既存ファイルを移動したりすることはありません。

### デフォルトの保存先

| OS | パス |
|----|------|
| Windows | `%USERPROFILE%\Documents\Pie Menu Editor\` |
| macOS | `~/Documents/Pie Menu Editor/` |
| Linux | `$XDG_DOCUMENTS_DIR/Pie Menu Editor/`（fallback: `~/Documents/Pie Menu Editor/`） |

既定のフォルダーは、アドオン本体と Blender の設定フォルダーから独立しています。
追加するリソースフォルダーには、共有フォルダーや読み取り専用の場所も指定できます。

## フォルダーの登録と操作

{guilabel}`Preferences` > {guilabel}`Settings` > {guilabel}`Resources` を開きます。
{guilabel}`Script Directories` の **+** ボタンを押すと、書類（Documents）フォルダーから選択画面が開きます。選んだフォルダーの名前が {guilabel}`Name` に入ります。
{guilabel}`Name` と {guilabel}`Path` は一覧で直接編集できます。Windows の {guilabel}`パスのコピー` などで付く前後の引用符は取り除きます。
`scripts/` を含むフォルダーを登録してください。登録したフォルダー自体の名前が `scripts` の場合や、直下に `autorun/` がある場合は、その行に一つ上のフォルダーを登録するよう案内が出ます。`icons` という名前のフォルダーは {guilabel}`Custom Icon Directories` に登録します。
アイコン用フォルダーの直下に PNG が無く `icons/` がある場合は、その `icons/` を登録するよう案内が出ます。

行末メニューには、その登録先のスクリプト・アイコンの件数と、フォルダーを開く・選び直す・
サブフォルダーを作成する・登録を削除する操作があります。
**登録の削除には確認が入り、最後の1件は削除できません。** フォルダー内のファイルは残りますが、そのフォルダーのスクリプトを使うスロットからは見つからなくなります。アイコン用フォルダーの登録は残るので、必要なら {guilabel}`Custom Icon Directories` から削除してください。
一時的に利用できない場所も登録は保持されます。見つからないパスは赤く表示されます。隣のフォルダーボタンから新しい場所を選んでください。

登録名は一覧と Quick Locations に表示する名前です。変更しても実際のフォルダー名や保存済みのスクリプト参照は変わりません。
すべての登録先を利用するため、一覧の先頭だけが有効になるわけではありません。

### Quick Locations と Examples

PME のファイル・フォルダー選択画面には、登録名を使った {guilabel}`Quick Locations` が表示されます。

| 選択画面 | 登録名を選んだときの移動先 | 追加の場所 |
|----------|--------------------------|------------|
| メニューの Import・Export | 各登録先の `exports/` | Import には {guilabel}`Menu Examples` と {guilabel}`Menu Backups` も表示 |
| スクリプト選択 | 各登録先の `scripts/` | {guilabel}`Script Examples` |
| リソース・保存先フォルダーの選択 | 登録フォルダーそのもの | — |

ショートカットはファイル名を保ったまま、ブラウザーのディレクトリを切り替えます。
存在しない移動先は利用できない状態で表示され、選択してもフォルダーは作成されません。

スクリプト選択の画面と手順は、{ref}`外部スクリプトをファイルブラウザーから選ぶ <external-script-browser>`を参照してください。

{guilabel}`Menu Examples` と {guilabel}`Script Examples` は、**アドオンに同梱した例を直接開きます。**
リソースフォルダーへのコピーは行いません。2.1.1 以前が作成したコピーはそのまま残ります。
例を編集する場合は、先に自分のリソースフォルダーへコピーしてください。

## 絶対パスと相対パス

### フォルダー設定のパス

フォルダー選択画面では、{guilabel}`Absolute` と {guilabel}`Relative` を選べます。
相対パスの基準は、**実行中の Blender の実行ファイル（Windows では `blender.exe`） があるフォルダー**です。
Relative のツールチップには、実際の実行ファイル名と基準フォルダーを表示します。
選択画面の {guilabel}`Go to Relative Path Base` で基準フォルダーを開けます。
たとえば `/opt/blender/blender` を実行している場合、`../PME-resources` は `/opt/PME-resources` を指します。

この規則はリソースフォルダー・メニューバックアップ・ログに共通です。
入力した相対パスは、保存・再起動後も相対パスのまま保持されます。
ホームディレクトリと環境変数は、パスを利用するときに展開します。
Blender の `//` は `.blend` 基準の指定として解釈せず、OS のパス規則に従います。
パスの書式と設定ファイルについては[起動オプション](boot_options.md)を参照してください。

### スロットに保存するスクリプト参照

登録先の中でファイルを選ぶと、**登録フォルダーからの相対パス**を保存します。
たとえば `Studio/scripts/modeling/align.py` を選ぶと `scripts/modeling/align.py`、`Studio/tools/align.py` を選ぶと `tools/align.py` が残ります。
このパスの `scripts/` は普通のフォルダー名で、特別な記法ではありません。
実行時は、この参照をすべての登録先で検索します。
どの登録先にもファイルがない場合は、アドオン本体の中を探します。
ただし、明示的な `assets/examples/scripts/...` 参照は、登録先に同じパスがあっても同梱例を使います。登録先でこの予約パスのファイルを選んだ場合は、選択したファイルを保つため絶対パスで保存します。
PME 1.x に同梱されていた例への参照（`scripts/command_hello_world.py` など）と、2.1.1 以前が `scripts/examples/` に複製した例への参照は、この版に同梱の例を使います。

フォルダー設定の `../PME-resources` と、スクリプト参照の `scripts/modeling/align.py` は基準が異なります。
前者は 実行中の Blender の実行ファイル（Windows では `blender.exe`） があるフォルダーから登録先を探すためのパス、後者は登録先からスクリプトを探すためのパスです。
**登録名をスクリプト参照に付けて、特定の登録先を選び分けることはできません。**
登録先の外で選んだファイルは絶対パスを保持し、同梱のスクリプト例はアドオン内の相対パスを使います。

## 同名ファイルと自動実行

### スクリプト参照の重複

`scripts/modeling/align.py` のような参照に対して、異なるファイルが複数見つかった場合は、
実行時に候補のパスを警告し、**どの候補も実行しません。** 登録順で優先することはありません。
同じ名前でも、`scripts/modeling/align.py` と `scripts/animation/align.py` は別の参照です。
ファイル名か下位フォルダーを変えて、参照を一意にしてください。
ユーザー側の場所を確認でき、該当するスクリプトがない場合だけ、アドオン本体の中を確認します。
同じ実ファイルに別のパスから到達した場合は、一つの候補として扱います。

{guilabel}`Settings` > {guilabel}`Resources` には、スロットで使われているかどうかにかかわらず、重複している `.py` のパスをすべて事前に表示します。
表示は登録先の追加・変更・削除で更新されます。共有フォルダーや大きなフォルダーの走査で起動を待たせないため、起動時には確認しません。Blender の再起動後や、Blender の外でファイルを追加・改名・移動した後は、{guilabel}`Script Directories` の **+** の隣にある更新ボタンを押してください。
走査できない場所がある場合は、その場所と、衝突一覧が不完全であることを警告します。対象の場所を確認してから再度更新してください。
`scripts/autorun/`・`scripts/register/`・`scripts/unregister/` のファイルは、すべて実行されるため表示しません。

スクリプトを移動・改名しても、保存済み参照は自動更新されません。
登録先・ファイル・参照の解決結果は、{ref}`読み取り専用のリソース API <resource-discovery>` からも確認できます。
この API は、各ファイルがどのスロットで使われているかを解析しません。

### カスタムアイコンの重複

アイコンは、登録したアイコン用フォルダーの直下にある `.png` ファイルを使い、拡張子を除いたファイル名で参照します。
**使用可能なアイコンは、すべてのアイコン用フォルダーから一つの一覧にまとめて表示します。**
異なるアイコン用フォルダーに同名アイコンがある場合、その名前のアイコンは選択一覧に表示しません。
{guilabel}`Settings` > {guilabel}`Resources` に、重複した名前とファイルパスを表示します。

重複した名前を同梱アイコンで代用することもありません。一意のユーザーアイコンは、同名の同梱アイコンより優先されます。
同じ実ファイルを別のパスから登録しても、重複としては扱いません。

### 自動実行用フォルダー

`autorun/`・`register/`・`unregister/` は、スロットからの参照とは別の規則で実行します。
PME は、すべての登録先にある各フォルダーの `.py` ファイルを下位フォルダーまで探し、各ファイルを直接実行します。
**別の登録先に同名のファイルがあっても、両方が実行対象です。** 同じ実ファイルへの別パスだけを重複除外します。

フォルダーを追加した直後には実行しません。自動実行の対象は、次の PME 起動・再有効化で読み込みます。

## 保存先と既存設定の移行

{guilabel}`Resources` 最下段の {guilabel}`Menu Backups` と {guilabel}`Logs` で、それぞれの保存先を指定します。
これらはリソースフォルダーと独立した設定です。登録名・パス・登録順を変更しても、出力先は変わりません。
**メニューバックアップに含まれるのはメニュー設定です。** スクリプトとアイコンのファイルは含みません。

場所の設定は[起動設定ファイル](boot_options.md)に保存します。
保存に成功するとすぐに反映され、Blender の Save Preferences は不要です。
保存に失敗した場合は、最後に保存できた設定を使い続け、未保存の項目を表示します。
パスを変更しても、既存ファイルは移動しません。

2.1.1 以前の単一フォルダー設定を移行するときは、そのフォルダーとファイル、設定済みのバックアップ先・ログ先を保持します。
未設定の保存先だけ、元のフォルダーの `backups/`・`logs/` から一度補います。
以後は独立した設定となり、リソース一覧の変更には追従しません。

### 複数端末での共有

リソースフォルダーは Syncthing・Dropbox・Git などのファイル同期ツールで共有できます。
自動バックアップのファイル名には、`backup_YYYY.MM.DD_HH.MM.SS_<environment-id>.json` のように環境識別子が付きます。
共有したバックアップ先でも、変更検出と世代保持を Blender 環境ごとに分離します。
識別子のない既存バックアップはそのまま保持されます。

メニュー定義（Pie Menu、Pop-up Dialog などの設定データ）は、リソースファイルとは別に保存されます。
メニュー設定をファイルで共有する場合は、{guilabel}`Export` > {guilabel}`All Menus` で JSON ファイルとして書き出してください。

## バージョン別のフォルダー構成

:::{dropdown} 単一フォルダー構成（2.1.1 以前）

2.1.1 では、一つのリソースフォルダーにスクリプト・アイコン・バックアップ・エクスポート・ログをまとめていました。
次の図は、その構成を記録したものです。

```text
Pie Menu Editor/
├── scripts/                    # ユーザースクリプト
│   ├── autorun/                # PME 起動時に自動実行されるスクリプト
│   └── examples/               # バンドル済みテンプレートからコピーされた例
│       ├── command_*.py
│       └── custom_*.py
├── icons/                      # カスタムアイコン
├── backups/                    # 自動バックアップ
│   └── backup_YYYY.MM.DD_HH.MM.SS_<environment-id>.json
├── exports/
│   └── examples/               # 初回起動時にコピーされるプリセット例
│       ├── 3d_view_numpad_pie.json
│       ├── mesh_select_mode_pie.json
│       └── ...
└── logs/                       # ログファイル
```

2.2.0 へ更新しても、これらのファイルはそのまま残ります。
`backups/` と `logs/` は、保存先に指定されていれば引き続き使用します。
Examples はパッケージを直接参照するようになり、`scripts/examples/` と `exports/examples/` へのコピーを行いません。
:::

:::{dropdown} リソース配置（1.19.2 以前）

PME 1.19.2 以前では、ユーザーリソースがアドオン本体の内部や隣接ディレクトリに保存されていました。
アドオンを上書きまたは削除すると、スクリプトやアイコンが失われる構造です。

### ディレクトリ構成

```text
addons/
├── pie_menu_editor/              # アドオン本体
│   ├── scripts/
│   │   ├── autorun/              # 起動時に自動実行されるスクリプト
│   │   │   └── functions.py      # システムファイル
│   │   └── ...
│   ├── icons/                    # カスタムアイコン（PNG）
│   ├── examples/                 # カスタマイズ例
│   ├── __init__.py
│   └── ...
└── pie_menu_editor_data/         # ユーザーデータ保護領域
    └── backups/                  # 自動バックアップ
```

### 各フォルダの役割

`pie_menu_editor/scripts/autorun/`
: PME 起動時に自動実行されるスクリプトの配置場所です。`functions.py` はシステムファイルです。

`pie_menu_editor/icons/`
: カスタムアイコン（PNG 形式）の配置場所です。アドオン本体内にあるため、上書きアップデートで消える可能性があります。

`pie_menu_editor_data/backups/`
: 自動バックアップの保存先です。アドオン本体とは別ディレクトリにあるため、上書きアップデートでは保持されます。

### Blender のアドオンディレクトリの場所

上記の `addons/` は、OS ごとに以下のパスにあります。

| OS | パス |
|----|------|
| Windows | `%APPDATA%\Blender Foundation\Blender\<version>\scripts\addons\` |
| macOS | `~/Library/Application Support/Blender/<version>/scripts/addons/` |
| Linux | `~/.config/blender/<version>/scripts/addons/` |

```{seealso}
PME2 への移行手順は {ref}`installation` を参照してください。
```
:::
